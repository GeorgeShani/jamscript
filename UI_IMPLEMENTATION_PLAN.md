# JamScript workbench implementation

Approved 17 October 2026. This plan supersedes the preview-only shell sections of `IMPLEMENTATION_PLAN.md`; that file retains the broader product roadmap.

## Milestone 1 — working browser IDE (implemented)

- Detach local Lovable build and reporting code, use the official TanStack Start Cloudflare Workers Vite integration, and keep existing Git history. Disconnect the Lovable project repository link in its Git settings before the first push of this work.
- Open a workspace chooser. Create app-managed browser workspaces and documents in IndexedDB; provide an explicit Night bus example, document CRUD, tabs, recent workspaces, autosave, and visible persistence errors. Native filesystem and Git stay desktop-only.
- Preserve each document's CodeMirror source, selection, scroll and undo state across tab changes. Playback and BPM always read the active editor; source controls use the checked lens patcher.
- Replace preview Repo, Takes, presence, Share, and Rework UI with Files, document tabs, Inspector, Output/Spectrum and actual transport state. Use the approved compact typography and 900px responsive breakpoint. A later real local Takes panel now appears in Output after successful playback; the example Takes rail remains unmounted.
- Install only audiocn Knob, Parameter Slider, Level Meter, Spectrum and their required hook/dependencies. Feed Inspector changes into source patches and meters from actual Strudel output, without demo signals.

## Milestone 2 — service-backed workspaces (Clerk account UI connected; Drizzle schema and authenticated membership listing prepared; sync and collaboration pending)

- Use Clerk for sign-in, session identity and account UI. The private Drizzle PostgreSQL schema and migrations now define workspaces, documents, memberships, invitations and revisions. Add authenticated server routes and user-scoped authorization before enabling sync or invitations; keep the schema outside Supabase's exposed API until a tested Clerk-to-RLS mapping exists.
- Add Liveblocks private per-document rooms with server-minted identity tokens and document permissions; then show presence and collaboration.
- Add server-side Gemini Ask/Edit chat (`/api/agent-chat`) and proposal (`/api/agent-proposal`) endpoints with explicit review/apply; show the Assistant pane only when `GET /api/agent-chat` reports `available:true` for a signed-in non-viewer shared editor. Live Gemini end-to-end remains a deployment verification.
- Keep workspace identity, documents, membership, revisions and sync in JamScript's own domain model. Git may become an optional desktop integration for users who want repository workflows; it is never required to create, save or share a workspace.

## Configuration and acceptance

The public site now lives at `/`. The browser workspace chooser is `/app`, individual browser workspaces open at `/app/workspaces/:workspaceId`, `/app/library` searches local documents, and `/app/help` documents current controls and shortcuts. These workspace URLs identify data in the current browser profile; they are not share links. `build:desktop-web` emits the workbench for the Tauri shell, which opens selected folders through native commands. Windows and Linux installers are not packaged yet. Keep public-site code outside that bundle and keep desktop navigation inside the workbench.

The browser workspace core needs no account. Clerk authentication uses browser-safe `VITE_CLERK_PUBLISHABLE_KEY` and Worker-only `CLERK_SECRET_KEY` from the selected application. Later services use browser-safe `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`, Worker-only `LIVEBLOCKS_SECRET_KEY` and `GEMINI_API_KEY`, and `APP_ORIGIN`; use `SUPABASE_SECRET_KEY` only for unavoidable privileged operations. Liveblocks also issues a public/publishable key (`VITE_LIVEBLOCKS_PUBLIC_KEY`), but this is optional and reserved for intentionally public demo rooms. Private workspaces use server-minted ID tokens from the secret key. Configure auth redirect URLs in their dashboards. Keep secrets out of client bundles and Git.

Verify IndexedDB creation/reload/CRUD/save errors, tab-specific undo and active playback, BPM and Inspector source patches, actual-output meter activity and silence on Stop, responsive keyboard access, no visible fixture actions, tests/lint/typecheck/build and Cloudflare preview.

Desktop responsiveness: native auth, collaboration, Git and filesystem commands run on blocking workers rather than the window thread. Filesystem/Git operations retain serialization to protect revision checks. Saved-folder watches register in the background. Shared workspace opening uses one membership-filtered query; database connection and shutdown waits are bounded. Desktop focus refreshes are throttled for 30 seconds and preserve loaded workspace rows.

Desktop account recovery distinguishes saved credentials from a verified account when Clerk DNS/network access fails. Credentials remain in the native store; local work stays available. The client makes at most three background checks and retries on an online event, coalesces overlapping profile requests, and ignores results from before sign-out/account switching. Cloud permissions still require successful verification. An opt-in Rust test checks the configured public Clerk metadata endpoint through the same native HTTP stack.

IntelliSense now uses TypeScript's offline language service in the shared worker for JavaScript type inference, member completion, signatures, definitions, references and rename. Generated Strudel declarations/documentation supplement that service; permissive musical argument types do not promise full static validation. Suggestions use the same themed list and documentation panel in browser and desktop, with documentation below the list at narrow widths. On 20 October 2026, live Gemini Ask and Edit were verified against synthetic local source, including proposal review/apply and normal editor undo. One transient busy response recovered through Retry; live provider availability remains external.

Strudel IntelliSense retains typed TypeScript displays in completions, hover and parameter hints. The API generator extracts source/JSDoc parameter types, optional/rest arguments, defaults, aliases and return types. Shared declarations model generic patterns, transformation callbacks, event/time records, control maps and sample maps/options. Registered transformations expose curried and explicit-pattern overloads; musical strings remain valid inputs. Undocumented types stay `unknown`. Regression checks compile the full declaration surface, verify callback/event inference and local shadowing, and accept the Coastline arrangement without false type diagnostics.

External sample loading now coalesces simultaneous URL requests, reuses cached audio, refreshes manifests after one minute and retries transient failures once with bounded timeouts. The desktop bridge queues bursts rather than rejecting the ninth simultaneous sample; eviction uses metadata without copying the full audio cache into the UI thread. Existing cached audio migrates in place. Host restrictions and file/cache size limits remain enforced; first-use audio is still lazy-loaded by Strudel.

Desktop account switching now opens `/desktop/connect` on the configured public API origin before device consent. The browser shows its current account with an explicit choice to continue or sign out there and use Clerk's enabled social/email methods. Native credentials remain in place until a replacement device grant succeeds. The desktop panel has a prominent code, browser action, pending state, dismiss/reopen behavior and clipboard fallback; no private-window instructions. Deploy the website route before distributing the updated desktop build; Google, GitHub and Apple must remain enabled in Clerk's instance configuration.

Desktop Git explicitly enables `git2`'s `https` feature; version 0.21 defaults to local repository support without HTTPS transport. Native tests assert TLS availability, and all three packaging jobs run them. A read-only GitHub refs probe was verified on Windows. Push remains non-forced, server ref rejections are surfaced, and stored GitHub credentials are restricted to github.com HTTPS remotes. The sidebar uses a dedicated clean state, separate changes/commit sections and collapsible remote settings; non-music changes and unsaved selected documents cannot be presented as a clean or committable music tree.

Git operation feedback uses directional commit markers while real Pull/Push requests are pending, then check or interruption states based on the service result. Refresh and commit have their own compact motion. Controls remain unavailable during an operation; there are no fabricated percentages or minimum animation delays. Motion pauses when the sidebar is offscreen or the document is hidden, and reduced-motion preferences retain static direction/outcome cues.

Database latency audit (20 October 2026): read-only probes found sub-3 ms Postgres execution but 2.6–3.6 s connection setup and 0.38–0.64 s warm local-to-Sydney round trips. Member listing now authorizes and joins invitation email in one query; the native HTTP agent shares its connection pool. Shared-project GET responses expose auth/database timings. The DB helper accepts an optional cache-disabled `HYPERDRIVE_FRESH` binding and skips unused array-type discovery; the direct transaction-pooler fallback remains available. Hyperdrive provisioning, binding its real ID, deployment and authenticated production timing remain pending. See README's database latency diagnostics; no database rows or schema were changed by the audit.
